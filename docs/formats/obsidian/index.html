Obsidian#

AI Generated, Human Reviewed at: 2026-11-24T00:30:38Z

Use it when your notes live in an Obsidian vault and you want to search them, follow their links and know which a person has checked, without changing how you write.

Install and switch it on#

pip install 'bowerbird-mcp[obsidian]'          # or: uvx --from 'bowerbird-mcp[obsidian]' bowerbird-mcp ...
# bower.yaml, at the root of the vault
format: obsidian
about: My notes.

The add-on ships in the one bowerbird-mcp package (bowerbird_obsidian.py): the extra adds nothing, it is the name you ask for, and format: obsidian is the switch. Everything else is the Markdown format: the same tools, the same sealing (.waxseals.yaml beside the files), and ADR records in it are sealed with an outcome as in ADR.

What it reads#

Markdown notes, anywhere in the vault. It leaves out .obsidian/ (the vault's settings, plugins and workspace) and .trash/.

You write Bowerbird reads it as
[[Note]], [[Note.md]] a link to the note named Note
[[Note\|alias]] the same link; the alias is only a label
[[Note#Heading]], [[Note#H1#H2]] a link to the note; the heading is checked against the note's headings
[[#Heading]] a link to a heading of this note
[[Note#^block-id]] a link to the note; the block id is not checked (Obsidian keeps it hidden in the text)
![[Note]], ![[Note#Heading]] an embed, read as a link
![[diagram.png]], ![[diagram.png\|300]] a link to the file: beside the note, from the vault root, or anywhere in the vault; the size part is ignored
[text](Note%20Name.md) a markdown link, as in every format
%% [[a comment]] %% nothing: a comment is not read
#tag, #nested/tag a tag of the note, beside the tags property (letters, digits, _, -, /; at least one letter or _; not in code, a comment or a URL)
aliases: [Other name] [[Other name]] finds this note

Links inside code (fenced or inline) are not read, in this format or any other.

How a name finds its note#

A link names a note by its path, ending with what you wrote: [[Note]] finds Note.md anywhere, [[Projects/Note]] finds Projects/Note.md. The .md is optional and the case is ignored. When several notes match, the one with the shortest path wins, then the one nearest the page that links. A name that finds nothing is a broken link, reported as a warning (dead_link), and links shows it with exists: false.

Obsidian's own documentation says how it writes links (the shortest unique path, or the full path from the vault root) but not how it resolves a name that two notes share, or whether case matters. Bowerbird's rule above is its own. If your vault depends on another, the warnings will show it.

Reviews and lint#

Seal a note as in Sealing; the review goes in a .waxseals.yaml in the note's folder, and the note is never edited. lint is offered here as in Markdown: it checks fact blocks and warns of a wikilink that leads nowhere (dead_link) or to a heading that is not there (dead_anchor).

Limits#

  • .canvas and .base files are found as the target of a link ([[board.canvas]]), but the links inside them are not followed.
  • [[## text]] and [[^text]] are searches in Obsidian, not links; they are reported as broken.
  • A comma-separated tags: a, b string is read as a list, though Obsidian's documentation does not say it is one.
  • A file named only for a date (2024-05-01.md) is a daily note, not an ADR record, so sealing it asks for no decision. A dated name with a title (2024-05-01-use-x.md) is a record, as in Markdown.

Tested against#

Made-up collections, not a real vault. The test builds this one in a temporary folder:

  • a.md holding [[b]], [[Missing]], %% [[Hidden]] %%, ![[img.png]], [[b#^blk]] and [[Alt Name]]; sub/b.md with aliases: [Alt Name]; img.png; .obsidian/workspace.md holding [[Nope]]; and t.md with tags: [fm] and #alpha #beta/sub #1984 %% #hidden %%#codehttp://x.y/#frag #x_1.
  • What the test checks: the comment's link is not read; [[b]] finds sub/b.md; ![[img.png]] finds the image; [[Alt Name]] finds sub/b.md by alias; .obsidian/ is left out; the only broken link reported is [[Missing]]; and the tags are fm, alpha, beta/sub, x_1, not #1984, #hidden, the code span or the URL fragment.

Nothing here has run against a real vault: only the small made-up collections above, in a temporary folder on Linux with Python 3.10, by the test suite (test_bowerbird_mcp.py). Windows and macOS paths, large vaults and Obsidian's own newer features are untested. The rules this page lists as unconfirmed come from Obsidian's own documentation, read second-hand.

Report a problem#

Something read wrong, a link reported broken that is not, or one missed: open an issue or write to dfoulks@voltpop.com. Say which format it is (format: obsidian), the version (bowerbird-mcp --version), and give the smallest note or two that show it, never your private ones. More on reporting a problem.
