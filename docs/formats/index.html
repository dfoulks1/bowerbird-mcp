Formats#

AI Generated, Human Reviewed at: 2026-11-24T00:25:45Z

Bowerbird is not tied to one way of keeping knowledge. A bower.yaml at the root of a folder says what the folder holds, with one line:

format: markdown      # markdown | adr | okf | skos | asciidoc | seal-only, or one an add-on supplies: obsidian | foam | dendron | logseq

All of them share the same ideas: the folder is a git repository, bower.yaml is committed with it, and a human's review is recorded against the exact bytes they reviewed (see Sealing). seal is what guarantees a person was in the loop, for stored knowledge and for decisions alike. Renaming a file with move keeps its seal when its text is unchanged.

Each format exists for a reason. Pick whichever fits what you keep; you can change your mind later (see Changing your mind).

  • Choose Markdown if you have notes, runbooks or docs, want to ask questions of them and know which a person has checked.
  • Choose ADR if you record decisions and want a person's review to be what makes one accepted.
  • Choose OKF if your knowledge needs sources, trust and freshness, kept by people and agents, and you want every tool.
  • Choose SKOS if you keep a controlled vocabulary: a glossary, taxonomy or thesaurus.
  • Choose AsciiDoc if your manuals and guides are written in AsciiDoc.
  • Choose Obsidian, Foam, Dendron or Logseq if your notes live in that tool and you want search, link checking and reviews over them as they are. Each is an add-on (see below).
  • Choose Seal-only if you need a guaranteed human review of code, configuration or any text files, and no search.

Each format's page has the same parts where they apply: when to use it, how to switch it on, what it reads, reviews (and lint), and its limits. The four add-on pages also say what they were tested against and how to report a problem.

What the Markdown formats share#

Markdown, ADR and the four add-on formats are all Markdown files, so they share these:

  • Wikilinks. [[Note]], [[Note#Heading]], [[Note|alias]] and ![[embed]] are links, as well as [text](note.md). links, backlinks, orphan and island see them. A name matches the file's path (the .md is optional, the case is ignored), the shortest path first, then the nearest to the page. OKF reads them the same way. AsciiDoc and SKOS files do not (in AsciiDoc, [[x]] is an anchor).
  • lint, offered to Markdown and ADR servers. It checks fact blocks and links that lead nowhere (dead_link, dead_anchor), as warnings. It does not judge the files as OKF concepts.
  • fact and factcheck, offered to Markdown and ADR servers: a claim and its source, written in the page and checked later (see Facts).
  • new, which starts a page from a template (markdown, adr or okf).
  • Reviews in a .waxseals.yaml in each file's folder. The file is never edited.

Format add-ons#

Obsidian, Foam, Dendron and Logseq write notes the same way (Markdown with [[wikilinks]]) and differ in the details: which side the alias is on, how a name finds a file, which folders are the tool's own. Bowerbird reads the shared part itself. What is particular to one tool lives in an add-on that ships in the one bowerbird-mcp package (a module beside the others), and format: <name> in bower.yaml selects it. The extra of the same name installs nothing more; it keeps the install line valid:

Format Install Page
obsidian pip install 'bowerbird-mcp[obsidian]' Obsidian
foam pip install 'bowerbird-mcp[foam]' Foam
dendron pip install 'bowerbird-mcp[dendron]' Dendron
logseq pip install 'bowerbird-mcp[logseq]' Logseq

Two other add-ons are not formats: the fact pack (five more kinds of fact) and seal-extensions (several people seal one version; see Sealing).

An add-on's files are Markdown, so each format behaves as Markdown (same tools, same sealing) with its own reading of links, tags and names.

Writing one. A third-party add-on is a Python package with an entry point in the group bowerbird.formats (the four above are bundled and need none), naming a function that takes the bowerbird_mcp module and calls register_format(name, ...). Every argument after the name is optional:

Argument What it does
about One line for the server's instructions: "an Obsidian vault".
skip Folder names the tool leaves out: its own state (.obsidian).
alias_first The alias is written first, [[alias\|note]].
page Turns a file's path (lowercase, without .md) into the page name a link uses for it.
clean Removes what is not a link from the body before links are read (Obsidian's %%comments%%).
links Links the tool writes besides wikilinks, each as [[Note#heading]].
virtual Says a page exists without a file (a Dendron stub, a Logseq journal).
quiet Lint kinds the tool's files are not held to.
lint A function (root, docs) returning the findings (finding(...)) for what the tool's files get wrong.
tags Turns the body into the inline #tags it holds (the frontmatter tags are always read).
names Turns a file's text and frontmatter into the other names its page answers to (aliases, a title::).
resolve Turns a link as written into a file: a path, None (no file, and not broken) or False (not this tool's: use the default).

A format that fails to load is said once on stderr and left out, so a broken add-on does not stop Bowerbird. The four above are modules at the root of this repository (bowerbird_obsidian.py and the rest); read one for a working example.

Changing your mind#

Change the format line and run bowerbird-mcp reindex; nothing else moves. Reviews are not converted between formats: an OKF concept keeps its verified entries in its own frontmatter, while the other formats keep theirs in .waxseals.yaml, so after a switch the notes may need sealing again. (okf export and okf import carry an OKF concept's reviews and sources to and from the ledgers: see the command line.)

Tools by format#

Which tools a server offers, by role. The role is what roles: in bower.yaml turns on (all five are on by default; --role or BOWERBIRD_ROLE picks one for a single server). Naming a role that is off refuses to start. The four add-on formats offer what Markdown does.

✓ a server offers it. CLI command line only (written for OKF files, so not offered outside OKF). — nothing to act on (seal-only indexes nothing).
